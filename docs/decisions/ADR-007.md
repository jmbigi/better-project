# ADR-007: Arquitectura MCP local

# REQ-023

## Contexto
El Model Context Protocol (MCP) requiere servidores que hablen JSON-RPC 2.0 por stdio. Inicialmente se configuro un MCP local `verify-local` apuntando a `bash scripts/verificar-proyecto.sh` con `cwd: "${workspace}"` (LSN-030). Esto fallaba porque:
1. `${workspace}` no es variable valida de opencode
2. Un script shell no implementa JSON-RPC

## Alternativas consideradas
1. **Script shell como MCP** - No viable (protocolo incompatible)
2. **Servidor Python JSON-RPC** - Implementar servidor MCP nativo
3. **Herramientas en servidor existente** - Exponer verificacion como tool del MCP `better-project`

## Decision
**Servidor MCP local único (`better-project`) en `scripts/mcp_server.py`** que implementa JSON-RPC 2.0 por stdio y expone 5 herramientas:
- `search_knowledge` - Busqueda en `.docs/knowledge/`
- `read_requirement` - Lectura de REQ-XXX
- `validate_requirements` - Trazabilidad REQ
- `create_lesson` - Registro de lecciones
- `run_verification` - Ejecucion de `verificar-proyecto.sh`

Eliminada entrada `verify-local` mal configurada de `opencode.json` y `kilo.json`.

## Consecuencias
### Positivas
- Protocolo correcto: JSON-RPC 2.0 por stdio
- Una sola conexion MCP, multiples herramientas
- Auditoría JSONL integrada (REQ-007)
- Límites de entrada aplicados en servidor (P0.13, REQ-007)
- Verificacion expuesta como tool, no como servidor aparte

### Negativas / Riesgos
- Servidor unico = punto unico de fallo (mitigado: simple, sin estado, reiniciable)
- `run_verification` tarda ~40s (mitigado: timeout 300s, asincrono en agente)

## Supuestos
- opencode/kilo soportan MCP local tipo `command: ["python3", "scripts/mcp_server.py"]`
- Los agentes usan las tools via MCP, no invocan scripts directamente

## Metricas de exito
- `opencode mcp list` muestra `better-project` enabled con 5 tools
- 0 errores de conexion MCP en uso real
- LSN-030 cerrada (resuelta)

## Pre-mortem (Análisis Prospectivo de Fallos)

- **Escenario 1 — Servidor MCP se bloquea/crashea**: el agente queda sin herramientas. *Mitigación*: servidor simple, sin estado, reiniciable automáticamente por opencode; timeout 300s en `run_verification`.
- **Escenario 2 — Cambio en protocolo MCP**: opencode/kilo actualizan y rompen compatibilidad. *Mitigación*: JSON-RPC 2.0 es estándar estable; tests de integración en `test_ecosistema.py::TestMCPServer` validan protocolo.
- **Escenario 3 — Límites de entrada evitan uso legítimo**: `MAX_LENGTHS` demasiado restrictivos. *Mitigación*: límites generosos (query 500, problema 2000); ajustables en código; auditoría JSONL registra rechazos para análisis.
