# ADR-009: Control de iteraciones con `steps` y rechazo de `seed`

# REQ-022

## Contexto

Los perfiles deterministas de `opencode.json` (`build`, `plan`, `audit`) usaban
`maxSteps` y `seed: 42`. La verificacion del `$schema` oficial
(`https://opencode.ai/config.json`, 21-09-2026) mostro dos hechos:

1. `maxSteps` esta marcado `@deprecated Use 'steps' field instead.`; el campo
   soportado para limitar iteraciones es `steps` (entero > 0).
2. `seed` **no** figura en `AgentConfig`. La documentacion "Additional" indica
   que las opciones no reconocidas se reenvian al proveedor como model option,
   sin garantia de que el modelo las respete.

Ademas, la documentacion interna se contradijo: `docs/ARQUITECTURA-DETERMINISMO.md`
(28-08-2026) decidio **no** adoptar `seed` (no verificable), mientras ADR-006
(20-09-2026) lo adopto como "validado empiricamente". El script
`scripts/test_determinism.py` ya advertia "esperado sin seed real en modelo".

## Alternativas consideradas

1. **Mantener `seed=42` y `maxSteps`** - minimo cambio, pero conserva un campo
   deprecado y una opcion no nativa que simula un determinismo no garantizado.
2. **Migrar a `steps` y conservar `seed` como passthrough** - usa el campo
   soportado, pero mantiene una dependencia del proveedor sin evidencia de que la
   respete.
3. **Migrar a `steps` y retirar `seed`** (elegida) - usa solo campos nativos y
   mide la varianza real con `temperature=0.0` y el test empirico.

## Decision

El bloque `agent` de `opencode.json` usa `temperature`, `top_p` y `steps`
(`build=50`, `plan=30`, `audit=20`); se retiran `seed` y `maxSteps`.
`scripts/verificar-proyecto.sh` valida `steps` y la AUSENCIA de `seed`/`maxSteps`.
La reproducibilidad no se reclama bit a bit: se maximiza con `temperature=0.0`
en `audit` y se mide por modelo con `scripts/test_determinism.py`.

## Consecuencias

- **Positivas**: configuracion conforme al `$schema` oficial; control de coste
  real via `steps`; se elimina una afirmacion de determinismo no respaldada.
- **Negativas / deuda asumida**: menor control de reproducibilidad que un `seed`
  real; la varianza depende del proveedor y del modelo.
- **Reversibilidad**: alta; revertir es reescribir el bloque `agent` y su check
  (coste bajo, 3 perfiles).

## Supuestos

- opencode 1.18.x sigue aceptando `steps` como maximo de iteraciones.
- La verificacion de esquema es estable mientras no cambie el `$schema` oficial.
- La varianza aceptable se decide por modelo, no por configuracion global.

## Metricas de exito

- Check "agente determinista" en `verificar-proyecto.sh` en verde (3 perfiles).
- `scripts/test_determinism.py` reporta el numero de salidas unicas (5 runs).
- Mutation score del batch >= 0.80 (medido 0.898 el 21-09-2026).

## Pre-mortem (Análisis Prospectivo de Fallos)

- **Escenario 1 — El proveedor deja de respetar `steps`**: el limite no acota
  consumo. *Mitigacion*: el check valida el campo segun el `$schema`; si el
  `$schema` cambia, se re-evalua el ADR con evidencia nueva.
- **Escenario 2 — Se necesita reproducibilidad estricta**: sin `seed` no hay
  replay exacto. *Mitigacion*: medir EMR con `test_determinism.py`; si un modelo
  documenta `seed` nativo, se reevalua su adopcion con evidencia.
- **Escenario 3 — Deriva documental**: otra doc vuelve a citar `seed`/`maxSteps`.
  *Mitigacion*: el check del verificador falla si reaparecen en `opencode.json`.
