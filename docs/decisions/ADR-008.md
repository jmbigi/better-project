# ADR-0004: Permisos bash

## Contexto
Los agentes necesitan ejecutar comandos bash pero deben estar limitados para evitar destruccion (P0.3), acceso a produccion (P0.4), sistema (P0.5), secretos (P0.6). La configuracion actual usa **denylist**: 304 patrones (218 `deny`, 85 `ask`, 1 `allow`) en `opencode.json` y `kilo.json`.

## Alternativas consideradas
1. **Allowlist pura** - Solo comandos explicitamente permitidos; todo lo demas `deny`
2. **Denylist actual** - Patrones peligrosos explicitamente bloqueados; resto `allow`/`ask`
3. **Hibrido** - Allowlist para comandos comunes, denylist para peligrosos

## Decision
**Denylist actual mantenida** con migracion planificada a allowlist (O8).

Patrones criticos `deny`:
- `rm -rf *`, `rm -r *`, `rm -f *` y variantes
- `git reset --hard*`, `git push --force*`, `git clean *`
- `psql * *DROP*`, `psql * *TRUNCATE*`, `mysql * *DROP*`, etc.
- `docker compose down -v*`, `docker kill*`
- `curl * | bash*`, `wget * | sh*`, `eval *`
- Lectura/escritura de `*.env`, `*.ssh/*`, `*.aws/*`, claves SSH

Patrones `ask` (requieren confirmacion):
- `rm *`, `git reset *`, `git push *`, `mv *`, `docker compose down*`
- Instaladores de paquetes (`pip install *`, `npm install *`, etc.)

Validado en `scripts/verificar-proyecto.sh`:
- 304 patrones exactos
- 218 deny, 85 ask, 1 allow
- kilo.json == opencode.json
- Ningun `ask` posterior anula un `deny` (test de matcher)

## Consecuencias
### Positivas
- Proteccion real: comandos destructivos bloqueados en agente
- Granularidad: `ask` para operaciones de riesgo, `deny` para irreversibles
- Sincronizado entre opencode y kilo

### Negativas / Riesgos
- **304 patrones = deuda de mantenimiento** (O8)
- Denylist crece indefinidamente; allowlist es mas sostenible
- Falsos positivos: `rm *` matchea `rm -rf x` (comportamiento documentado)
- Complejidad de matcher: primer segmento del pipeline

## Supuestos
- El matcher de opencode evalua primer segmento antes de `|`
- Patrones `*` = wildcard greedy (cero o mas caracteres)
- `ask` se auto-aprueba en modo `--auto`; proteccion real son los `deny`

## Metricas de exito
- 0 comandos destructivos ejecutados sin autorizacion
- Verificador pasa: 304 patrones, conteos exactos, sin ask-anula-deny
- Migracion a allowlist < 80 patrones (O8) en 6 meses
