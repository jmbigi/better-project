# REQ-021: Definir proposito del proyecto

## Contexto
El proyecto `better-project` tiene una identidad ambigua: ¿es un **producto** (aplicación usable por usuarios finales) o un **meta-proyecto** (framework metodológico para gobernar proyectos con agentes)? Esta ambigüedad invalida cualquier puntuación global (el 96/100 anterior no significa nada sin esta definición).

## Criterios de aceptación
- [ ] ADR-0001 creado en `docs/decisions/ADR-0001.md` declarando el proposito
- [ ] README actualizado con la definicion explicita
- [ ] Todos los REQs existentes revisados para coherencia con el proposito declarado
- [ ] Documento firmado (commit con trailer Assisted-by) y referenciado desde README

## Metrica de exito
Binario: proposito declarado y documentado = 1, sinon = 0.

## Justificacion
Sin esta definicion, no se pueden establecer KPIs validos, no se sabe si la demo (3 REQs) es suficiente o insuficiente, y no se puede priorizar el trabajo (O10, O11, O14 dependen de esto).
