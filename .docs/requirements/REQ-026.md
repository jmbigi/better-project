# REQ-026: Ejecucion de tests aislada por proceso

## Contexto

La suite (`tests/`, 357 casos) se ejecutaba en un unico proceso con
`python3 -m unittest discover -s tests -q`. Todo el estado de los modulos se
acumula hasta el final: con las dependencias opcionales instaladas
(torch/sentence-transformers via `index_knowledge`, chromadb, llama.cpp) el
pico de memoria crece sin liberarse entre tests y puede provocar OOM en
equipos con poca RAM. Ademas, una fuga de estado en un test contamina los
siguientes.

## Criterios de aceptacion

1. `scripts/run_tests_isolated.py` descubre cada test y lo ejecuta en un
   subproceso independiente (`python3 -m unittest <id>`), devolviendo la
   memoria al terminar cada uno.
2. Salida agregada (total, pasados, fallidos) y codigo de salida 1 si algun
   test falla o da error; timeout explicito por test (P1.34).
3. `scripts/verificar-proyecto.sh` y `scripts/ci.sh` usan el runner como
   comando de tests del ecosistema.
4. Respeta la guarda anti-recursion `BETTER_TEST_INTEGRACION`: dentro de la
   copia temporal (REQ-010) ejecuta el resto de la suite in-process, para no
   anidar cientos de subprocesos; los tests de integracion se omiten.

## Metrica de exito

Pico de memoria acotado al de UN subproceso (no a la suma de la suite); 0
OOM en la ejecucion completa con dependencias opcionales instaladas.
