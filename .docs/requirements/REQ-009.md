# REQ-009: Pipeline de verificacion local (CI sin proveedor)

> v1.1 (2026-09-04): reescrito por orden del programador — el proyecto NO
> puede depender de proveedores tipo GitHub/GitLab; la verificacion se
> implementa con herramientas open source y locales (git, bash, python3
> stdlib). La version 1.0 (GitHub Actions) queda descartada.

`scripts/ci.sh` actua como CI local: exporta el HEAD del repo a un
directorio limpio (equivalente a un clon fresco: detecta dependencia de
archivos sin commitear, que es lo que un CI remoto pillaría) y ejecuta alli
toda la verificacion, como red externa al hook local (que puede omitirse
con `git commit --no-verify`).

## Criterios de aceptacion

1. Exporta `git archive HEAD` a un directorio temporal e informa de
   archivos modificados/sin commitear que quedan FUERA de la verificacion.
2. En la copia limpia: `py_compile` de los scripts, suite unittest
   (`python3 -m unittest discover -s tests -q`) y
   `bash scripts/verificar-proyecto.sh --pre-commit` (con git init +
   hook instalado para que los checks de repositorio apliquen).
3. Sin dependencias externas ni red: solo git, bash y python3 stdlib.
4. Codigo de salida 0 solo si todo pasa; mensajes claros de que fallo
   (fail fast, P1.26).
5. Propaga `BETTER_TEST_INTEGRACION=1` para evitar recursion de la suite.
6. `bash -n` limpio y verificado ejecutandolo sobre el repo real.
