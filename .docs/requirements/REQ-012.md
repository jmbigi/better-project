# REQ-012: Integracion de Jev con los tres pilares del ecosistema

> v1.0 (2026-09-19): aprobado por el programador e implementado. Evidencia de
> verificacion en `docs/ESTADO-JEV-LLAMA.md`. Las propuestas del motor son
> **asistidas y no autoritativas**: el humano decide (P1.17/P1.23).

El motor Jev (REQ-011) expone decisiones tipadas (`noul`, `choice`, `score`)
con probabilidades calibradas. Este requisito lo integra como **capa de
clasificacion asistida** (no autoritativa) sobre los tres pilares del
ecosistema: requisitos, conocimiento y lecciones. La clasificacion **propone**;
el humano decide (P1.17/P1.23). No reemplaza los guardarrailes deterministas.

## Alcance

`scripts/jev_pillars.py`, con tres subcomandos:

1. `requisitos` — dado un REQ del repo (`--req REQ-XXX`) o un texto
   (`--file`/`--text`), propone la `prioridad` (choice: Baja/Media/Alta).
2. `conocimiento` — dado un fragmento de `.docs/knowledge/` (`--file`) o texto,
   propone una `puntuacion` ordinal 0-3 de relevancia/calidad.
3. `lecciones` — dada una leccion (`--file` o `--id LSN-XXX`), propone la
   `fase` (choice: Diseno/Implementacion/Testing/Deploy) y `categoria`
   (choice: Proceso/Seguridad/Riesgo_Tecnico).

## Criterios de aceptacion

1. CLI `scripts/jev_pillars.py <subcomando>` con `--json`; encabezado con
   `# REQ-012` en el script.
2. Lee de `.docs/requirements/`, `.docs/knowledge/` y `.docs/lessons/`, o de
   `--file`/`--text`; **nunca escribe** en esas rutas (solo propone).
3. Usa el motor de REQ-011 (`JevLlama`) y respeta `JEV_TEMPERATURE`; falla
   explicito si falta el modelo, la dependencia o la entrada es invalida
   (P1.26).
4. Umbral de confianza `JEV_MIN_CONFIDENCE` (default 0.5): si la confianza de
   la decision es menor, la salida marca `revision_humana: true` y no emite
   etiqueta definitiva (rechazo por baja confianza).
5. Salida JSON con esquema fijo:
   `{"id", "tipo", "decision", "probabilities", "confidence", "revision_humana"}`.
6. Reutiliza el set de calibracion (REQ-011) para reportar la accuracy por
   tarea; si la accuracy medida de una tarea es < 0.6, el subcomando se marca
   `experimental: true` y no puede usarse como guardarrail (el tipo `score` ya
   se midio en 0.417).
7. Tests unitarios con mocks (sin modelo) para los tres subcomandos, el umbral
   de confianza y los errores; test de integracion opcional si existe
   `JEV_MODEL_PATH`.
8. No modifica automaticamente ningun REQ, leccion o documento; la aplicacion
   de una propuesta es una accion humana explicita (P1.17/P1.25).
9. Verificacion: `python3 -m py_compile`, `python3 -m unittest discover -s
   tests -q` y `bash scripts/verificar-proyecto.sh` en verde, con evidencia en
   `docs/ESTADO-JEV-LLAMA.md`.
10. Documentacion en `.docs/knowledge/ai/jev_pillars.md` (uso, umbrales,
    limitaciones y precision medida por tarea).

## Fuera de alcance

- Aplicar cambios automaticamente a requisitos/lecciones/conocimiento.
- Entrenamiento, fine-tuning o uso de GPU.
- Servir como guardarrail para decisiones criticas sin revision humana.

## Dependencias

- REQ-011 (motor Jev) y su set de calibracion.
- `llama-cpp-python` (opcional) y un GGUF local; Python stdlib para el resto.

## Riesgos

- La calidad del modelo es desigual por tipo (`score` 0.417, `noul` 0.625,
  `choice` 0.917 medidos). Mitigacion: umbral de confianza, marca
  `experimental` y revision humana obligatoria.
- Las etiquetas del set de calibracion aun no tienen revision humana (P1.15);
  la accuracy por tarea es provisional hasta esa revision.

## Plan de verificacion

- Unitarios con mocks: subcomandos, umbral, errores, sin modelo.
- Integracion (opcional, con `JEV_MODEL_PATH`): demo sobre un REQ, un fragmento
  de conocimiento y una leccion reales.
- Metricas por tarea usando `scripts/jev_calibration.py` como base.
